## 4. Cryptographic Report Snapshot & Immutability Engine

Every assessment report snapshot is mathematically sealed upon generation:
1. **Canonical Serialization:** The report content dictionary is deterministically serialized to JSON (`sort_keys=True, separators=(',', ':')`).
2. **SHA-256 Checksum:** `checksum = SHA256(canonical_json)`.
3. **Database Immutability:** Stored in `report_snapshots` alongside `schema_version`, `system_version`, and `data_foundation_version`.
4. **Live Verification:** On every retrieval, `SnapshotManager.verify_integrity(snapshot)` recomputes the SHA-256 hash and validates it against the stored checksum. If content is modified in the database, `is_tampered` is automatically flagged as `true`.

## 5. Append-Only Cryptographic Audit Trail

The SAT-SA audit system maintains an unbroken cryptographic ledger of all supervisory actions:
- **Hash Chaining Formula:**
  $$\text{Integrity Hash}_i = \text{SHA-256}(\text{Integrity Hash}_{i-1} \parallel \text{Timestamp} \parallel \text{User ID} \parallel \text{Role} \parallel \text{Action} \parallel \text{Entity Type} \parallel \text{Entity ID} \parallel \text{Status} \parallel \text{Payload})$$
- **Tamper Detection:** The `verify_audit_trail_integrity()` validator inspects all sequential records, validating both the payload hash and previous hash link continuity.
- **Rich Querying:** Supports indexed filtering by user, role, action, entity type, entity ID, status, correlation ID, and date range with fast pagination.

## 7. REST API Endpoints

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `POST` | `/api/v1/reports/generate` | Generates, cryptographically signs, and stores an immutable report snapshot |

| `GET` | `/api/v1/reports/{report_id}` | Retrieves full report snapshot details with live cryptographic tamper verification |
| `GET` | `/api/v1/reports/{report_id}/export` | Exports report snapshot in `json` or `html` format |
| `GET` | `/api/v1/reports/{report_id}/evidence` | Retrieves all evidence references and provenance linkages |
| `GET` | `/api/v1/audit/logs` | Queries and filters append-only cryptographic audit logs |
| `GET` | `/api/v1/audit/logs/{id}` | Retrieves specific audit event details and before/after diffs |
| `GET` | `/api/v1/audit/verify` | Verifies cryptographic hash chaining integrity across entire audit history |
| `POST` | `/api/v1/audit/events` | Explicitly records a new audit event into the cryptographic ledger |
